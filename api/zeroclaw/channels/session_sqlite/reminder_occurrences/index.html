Module reminder_occurrences 

Expand description

Scheduler-owned reminder occurrences (#568): the durable intent that a committed task list item deserves attention at a time. The store is owned by the reminder scheduler — the task_list tool arms occurrences inside the task batch transaction, and the gateway producer (reminder_notifications) is the only writer of enqueued/invalidated beyond that path. Per ADR-020 §5 this is NOT a column on the task table: the occurrence is the modifiable truth, the task only projects “has a reminder”.

Fire-once: the occurrence row itself is the durable marker (no eviction); the outbox’s (source_kind, source_id, event_id) dedup only covers the enqueue→mark crash window. expires_at = due_at + 24h is ABSOLUTE — an occurrence first observed by a producer long after its due time is past validity and never enqueues (today’s enqueue-relative outbox TTL would otherwise let a month-old reminder open a fresh delivery window).
