Module api_soul 

Expand description

/api/soul/* — the owner surface of the governed Soul (ADR-015 §7).

Every route is operator-gated: the agent’s Identity and Principles are owner authority, and no model tool, channel identity, or bridge message reaches these handlers. Writes are append-only revisions with an expected-revision check, so a stale editor gets 409 instead of silently overwriting a newer value.

Functions§

get_drift
GET /api/soul/drift?agent= — the agent’s current anchor and its deterministic drift (ADR-018 §4.3). Read-only: a default anchor is derived, never stored, by this call.
get_export
GET /api/soul/export?agent= — canonical layers and history only. No seeding, proposals, reflection receipts, or private evidence notes.
get_history
GET /api/soul/history?agent=&layer=identity|principles|tone|tone_exemplars|story — every revision of one layer, oldest first.
get_proposals
GET /api/soul/proposals?agent=[&pending=true] — the agent’s own proposals to change its principles or tone, oldest first.
get_soul
GET /api/soul?agent= — current Identity and Principles heads (with revision and source), effective Tone with per-key provenance and the Tone exemplars head (tone.exemplars, or null), and whether the legacy persona files are still injected. Seeds missing layers on first read, exactly as the prompt builder does.
post_anchor
POST /api/soul/anchor — “keep”: move the anchor to the current Tone and Story heads. Both expected revisions must be the current heads, else 409 revision_conflict.
post_anchor_rollback
POST /api/soul/anchor/rollback — “roll back”: append Tone and Story revisions equal to the anchor’s, in one transaction, through the same path as /api/soul/rollback. A layer already equal to the anchor is left alone (null). The anchor does not move. Stale expected revisions get 409 revision_conflict and write nothing.
post_resolve_proposal
POST /api/soul/proposals/{id}/resolve — the owner’s decision on one of the agent’s proposals (ADR-016 §3). accepted applies the proposal to its layer in the same transaction (optionally reworded with final_text) and returns the applied revision; dismissed applies nothing. Each proposal resolves once. If the change can no longer apply (an invalid field, or a Story retirement whose entry the owner has since removed or reworded), the proposal stays pending and nothing is applied.
post_rollback
POST /api/soul/rollback — append a new revision equal to an earlier one.
put_identity
PUT /api/soul/identity — owner-authored Identity revision. After the first one, the legacy SOUL.md / IDENTITY.md files stop being injected.
put_principles
PUT /api/soul/principles — owner-authored Principles revision.
put_story
PUT /api/soul/story — owner rewrite of the Story layer (for example to retire several entries at once or correct the agent’s wording).
put_tone
PUT /api/soul/tone — owner write of the stored Tone heads, which layer over the configured persona dials key by key. The owner may set any level.
put_tone_exemplars
PUT /api/soul/tone/exemplars — owner write of the Tone exemplars (ADR-018 §3): at most four single-line examples of how the agent sounds. The agent has no path to this layer; it is written only here. expected_revision is 0 when there are none yet; a stale one returns the revision_conflict 409.
