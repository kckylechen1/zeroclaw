Function apply_persisted_proxy_on_boot 

pub fn apply_persisted_proxy_on_boot(proxy: &ProxyConfig)
Expand description

Reapply the persisted canonical [proxy] config at process startup.

The model-visible proxy_config tool no longer registers, so the persisted config file is the only way proxy state changes; the daemon must therefore make the loaded file effective on its own:

  • the runtime proxy global (read by every proxy-aware client builder) is seeded unconditionally, whatever the scope, and
  • process proxy environment variables are broadcast only when the config is enabled with scope = "environment", matching the condition the retired apply_env action enforced.

A config that fails validate() is applied disabled (mirroring the original config-load behavior): the global gets the explicit default and no environment variable is written. Callers must invoke this once per process boot, before the multi-threaded async runtime (and any task that reads proxy environment variables) starts — process-env mutation is only sound there. A daemon reload refreshes only the runtime global (set_runtime_proxy_config), keeping live-env application restart-only.
