Module persona_projection 

Expand description

Governed Soul projection (ADR-015 §2, §6).

Renders the agent’s persona section from four sources, in order of precedence (ADR-018 §2):

  1. ## Identity: the owner-governed Identity layer of the Soul profile store, plus a fixed honesty line (ADR-015 §5);
  2. ## Principles: the owner-governed Principles layer;
  3. ## Tone: the configured persona dials (PersonaKnobs) with any stored Tone heads layered over them key by key, then the owner’s Tone exemplars (ADR-018 §3) under a fixed framing line;
  4. ## Our story so far: the Story layer (ADR-016), changed only by owner-approved proposals or by the owner. It comes after Tone because Tone decides how the agent sounds when the two disagree.

Only owner-written text, owner-approved proposal text, seeded defaults, and repository-owned strings can render. Each layer is byte-bounded and truncated by whole lines only.

The same profile and config always produce the same bytes, whatever the model, provider, or channel carrying the turn.

Legacy SOUL.md / IDENTITY.md workspace files keep being injected until the owner writes an Identity revision; after that they are suppressed so there is one persona source. USER.md retires the same way, decided separately: once the User Model holds an owner-authorized active revision for the agent, USER.md is no longer injected (ADR-018 §6).

If the store cannot be opened or read, the outcome depends on whether it was ever initialized. With no soul.db yet (first run), the legacy files stay the persona source. With an existing soul.db, the identity it holds is unknown, so the projection degrades: legacy files stay suppressed, a fixed line says the identity is unavailable, and the configured Tone applies. Nothing replaces the damaged store; the next turn retries. A User Model that cannot be read never fails the turn: USER.md keeps being injected and one WARN is logged.
